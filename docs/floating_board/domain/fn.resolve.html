Expand description

Pure placement resolution: card geometry + footprint + layout + measured items -> one SatellitePlacement per item, in workspace coordinates.

The sidebar path lets EdgeStripLayout arrange items in the card-local frame (card center at the origin, natural footprint), then maps each placement through the card transform: scale, rotate about the card center, translate. Widget orientation follows mode (CoRotate -> card rotation, the upright modes -> no rotation); positions are always card-local for a sidebar - CounterRotate orbit semantics are radial matter (Phase 3). Satellites inherit the card’s scale factor (rigid docking).

The Radial path lets OrbitLayout place items on an arc around the card-local center (radius = distance outward from the card’s bounding circle via orbit_radius_for), then maps through the same card transform. CounterRotate is radial-only semantics: orbit angles stay screen-fixed - positions scale and translate but do not rotate with the card, so rotating the card orbits nothing while dragging carries the whole ring along.
