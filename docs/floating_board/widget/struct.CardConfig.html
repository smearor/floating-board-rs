Expand description

Placement and interaction configuration of a card.

Passed to FloatingBoard::add_card; all fields have defaults so CardConfig::default() yields a fully interactive, draggable card anchored at the board center.

Fields§

§title: Option<String>

Title shown in the header strip; falls back to a localized default when the header is visible and no title is set.

§position: CardAnchor

Initial placement anchor, resolved on first allocation.

§draggable: bool

Whether the card can be moved by dragging.

§rotatable: bool

Whether the card can be rotated via the two-finger rotate gesture.

§scalable: bool

Whether the card can be scaled via the pinch gesture.

§resizable: bool

Whether the card shows a bottom-right resize grip that scales the card around its center when dragged (mouse and touch).

§rotate_grip: bool

Whether the card shows a bottom-left rotate grip that steps the rotation to the next quarter turn in the swipe direction - one quarter turn per drag, no matter how far the swipe goes (mouse and touch). Works independently of rotatable, which gates the free two-finger rotate.

§foldable: bool

Whether the card can be folded down to its header.

§closable: bool

Whether the header shows a close button.

§close_action: CardCloseAction

What the close button does - remove the card (default) or hide it so a menu can re-open it later.

§headerless: bool

Collapses the header to a slim grip when no title/buttons are needed.

§drag_handle: DragHandle

Which part of the card acts as the drag affordance.

§shape: CardShape

The card’s outline shape - Rectangle (default) or Circle.

A circle card has no header strip and no corner grips: inline chrome mounts along the disc’s arc bands (arc_span on top, arc_bottom_span on the bottom), Satellite placements stay satellites, the edge grips are dropped with a warning at mount, and taps in the bounding-box corners pass through to whatever is underneath.

§circle_content: CircleContent

How a Circle card allocates its content inside the bounding square. Ignored for Rectangle.

§arc_span: Option<Degrees>

Angular span of the arc-chrome band on CardShape::Circle - the top arc the inline chrome items ride on, centered on the disc’s top. None defaults to Degrees::QUARTER_TURN (90°); values above a full turn are clamped. Ignored for Rectangle and for circle cards without inline chrome.

§arc_bottom_span: Option<Degrees>

Angular span of the bottom arc-chrome band on CardShape::Circle. None mirrors arc_span; set it when the bottom band should wrap a different share of the rim than the top band. Ignored for Rectangle and for circle cards without ArcBottom* chrome.

§anchor_margin: Pixels

Margin in pixels an edge or corner anchor keeps between the card’s footprint and the board edge; default ANCHOR_MARGIN (24 px). Ignored for Center and Explicit placements.

§scale_limits: ScaleBounds

Inclusive scale limits for the pinch gesture; default 0.5 - 2.0.

§min_visible: MinVisible

Minimum overlap in pixels a card must keep inside the board bounds.

§bounds_mode: BoundsMode

How strictly the card’s footprint is kept inside the board bounds; default Loose (only min_visible is enforced).

§palette: Option<CardPalette>

Per-card color scheme: a CardPalette mapped onto scoped CSS at build time. None (or a palette with unfilled slots) keeps the themed/default-card colors.

§content_padding: Pixels

Space in pixels between the card border and the content widget; default DEFAULT_CONTENT_PADDING (10 px, the former fixed CSS value). 0 lets the content sit flush with the card edge.

§z_index: Option<i32>

Optional initial z-ordering; None appends the card on top.

§max_width: Option<Pixels>

Hard upper bound on the card’s measured width; None lets the card grow with its content. Caps growth caused by changing content (e.g. a number gaining a digit): the layout allocates at most this size and overflowing content is clipped by the default CSS.

§max_height: Option<Pixels>

Hard upper bound on the card’s measured height; see max_width.

§animation_speed_ms: u64

Duration of rotation animations (gesture snapping and set_rotation_with_animation) in milliseconds; default 500.

§seat: Option<Seat>

Optional seat assignment on the tabletop edge the card belongs to - decoupled from the card’s visual rotation: rotating the board or freely spinning the card does not change which user owns it. None leaves the card unassigned; seat strategies and rotate_to_next_user fall back to the nearest side of its rotation.

§folded_content: Option<Widget>

Custom widget shown while the card is folded. When set, folding collapses the whole card - header included - to this widget and adds the floating-card-collapsed class, so a round button or a compact mini view can replace the full card. None keeps the default fold that leaves the header strip visible.

The folded widget should offer an unfold affordance wired to Card::set_folded(false) or Card::fold - the card’s own fold button hides with the header. unfold_on_click provides a ready-made affordance for cards without one.

§unfold_on_click: bool

A click on the folded card unfolds it (revealing the satellite set again). The click gesture only releases on sequences the card drag did not claim, so moving a folded card never unfolds it. While enabled the circle card’s Minimize fold exception is unnecessary - the card is one tap away from unfolding - so the satellite closes with the rest of the set.

§fold_animation: CardFoldAnimation

How the card transitions between unfolded and folded presentation (CardFoldAnimation): an eased program over the axes width, height, rotation, zoom and content opacity, budgeted by animation_speed_ms. Instant (default) swaps atomically; reduced motion lands instantly too.

§unfold_animation: Option<CardFoldAnimation>

The morph program for the unfold direction - None replays fold_animation mirrored, so a single setting animates both directions.

§fold_timing: CardFoldTiming

When an animated fold plays relative to the satellite close choreography: Sequential (default) morphs after the last satellite sank into the card, Overlap(fraction) starts the morph mid-close (0.0 = parallel). Unfolds always morph while the set reveals.

§unfold_timing: Option<CardFoldTiming>

The unfold-direction choreography timing relative to the satellite reveal - None resolves to Overlap(0.0), the morph and the reveal run in lockstep.

§sticky: bool

Pins the card to the screen instead of the workspace: a sticky card ignores the View camera entirely and keeps its on-screen position, rotation and zoom while the view pans, zooms or rotates. Its stored geometry is then expressed in widget pixels; toggling converts between the two spaces, so pinning never moves the card visually. Sticky cards are skipped by apply_layout, and passing one to a seat releases the pin.

§chrome: Option<Vec<ChromeSlot>>

Explicit chrome composition as an ordered slot list (CardConfig::chrome).

  • None (default): derive slots from the legacy flags (title/title_label -> Title, foldable -> Minimize, closable -> Close, resizable -> ResizeGrip, rotate_grip -> RotateGrip, drag_handle == Handle -> DragHandle; all Inline).
  • Some(slots): overrides the legacy-derived chrome entirely - the list is the complete chrome description. Satellite placements are validated at build time; until satellite mounting lands they are skipped (no inline fallback).
§chrome_style: ChromeStyle

Which renderer draws the chrome (CardConfig::chrome_style): Builtin (default) or Adwaita (requires the adwaita feature; falls back to Builtin without it).

§satellites: Option<CardSatellites>

Satellite configuration: layout, rotation and collision semantics plus the explicit satellite list (CardSatellites). None (default) means no custom satellites; chrome elements configured ChromeSlot::satellite(..) still mount with the CardSatellites defaults (sidebar below the card).

The effective ordered chrome slots - either the explicit CardConfig::chrome list or the list derived from the legacy flags (default: DragHandle, Title, Minimize, Close, ResizeGrip, RotateGrip, all Inline; elements whose flag is off are absent).

Source

pub fn effective_satellites(&self) -> (CardSatellites, Vec<SatelliteConfig>)

The effective satellite set: ChromeSlot::satellite entries in slot order (elements that cannot be satellites are warned about once at mount), then the explicit CardSatellites::satellites list. Layout, rotation and collision semantics come from satellites, defaulting to a CoRotate sidebar below the card.

Non-satellite placements are never satellites: on Rectangle they mount in the header strip, on Circle in the top-arc chrome band (Card::mount_chrome owns both mounts).
